# 像素跑酷 Pixel Parkour

一个 HTML5 像素风横版平台跑酷游戏（Phaser 3 + TypeScript + Vite）。
**地图是纯 ASCII 文本，加一张新地图 = 新建一个 .ts 文件，不用改任何其他代码。**

## 快速开始

```bash
npm install
npm run dev          # 打开 http://localhost:5173（游戏）；editor.html 是地图编辑器
npm run build        # 生产构建（输出到 dist/，可直接丢到任意静态服务器）
npm run check:maps   # 校验所有地图：结构（必须全过）+ 可通关性仿真（参考）
npm run gen:map      # 自动生成一张地图（难度 0.5，见下文「自动生成地图」）
```

调试单关：`http://localhost:5173/?level=2`

## 操作

| 动作             | 按键                        |
| ---------------- | --------------------------- |
| 左右移动         | `←` `→` / `A` `D` |
| 跳跃 / 二段跳    | `Space` `↑` `W`      |
| 冲刺（可冲刺跳） | `Shift` `Z`             |
| 下穿单向平台     | `↓` + 跳                 |
| 暂停             | `Esc`                     |
| 原地重开         | `R`                       |

手感细节：土狼时间 0.09s、跳跃缓冲 0.1s、可变跳高（松键截断）、蹬墙滑行 + 蹬墙跳、冲刺带无敌帧位移、落地/蹬墙粒子与镜头轻震。

## 加一张地图(parkour-map-maker.SKILL为ai生成地图技能)

不想手写 ASCII？项目还提供了两条可视化路径：**图形化地图编辑器**（下节）和**自动生成器**（下下节），手写、画图、自动生成任选。

### 三步走

1. 在 `src/levels/maps/` 新建文件，例如 `04-my-level.ts`（**文件名前缀决定选关顺序**，建议两位数字编号）。
2. 照抄下面的模板，改 `meta` 和 `grid`。
3. 保存，刷新页面 —— Vite 的 `import.meta.glob` 会自动注册，选关界面立刻出现新关卡。

```ts
import type { LevelData } from '../../core/map-format';

const level: LevelData = {
  meta: {
    id: 'my-level',        // 全局唯一，存档 key，别和其他图重复
    name: '第四关：我的关卡',
    hint: '选关界面里的一句话提示',
  },
  grid: [
    '................',
    '.....o..........',
    '.S......^^^....E',
    '################',
    '################',
  ],
};

export default level;
```

模板已通过 `check:maps` 校验。注意尖刺 `^^^` 是 **3 格宽**——跑跳水平距离约 6 格，尖刺组宽 **≤ 4 格**才跳得过去（起跳 1 + 尖刺宽 + 落地 1），别排一整排。

### 地图字符表

| 字符         | 含义                                       | 字符          | 含义                                |
| ------------ | ------------------------------------------ | ------------- | ----------------------------------- |
| `#`        | 实心方块（墙 / 地面）                      | `S`         | 出生点（每张图**恰好 1 个**） |
| `=`        | 单向平台（可从下往上跳穿，`↓`+跳 下落） | `E`         | 终点传送门（至少 1 个，碰到即通关） |
| `-`        | 装饰横木（无碰撞）                         | `C`         | 检查点（死亡后从此处复活）          |
| `^`        | 尖刺（碰到死亡，需坐在实心块上）           | `B`         | 弹跳板（弹起约 7 格高）             |
| `~`        | 岩浆（碰到立即死亡）                       | `M` / `m` | 水平 / 垂直移动平台（会载着你走）   |
| `o`        | 金币                                       | `>` `<`   | 向右 / 向左加速带                   |
| `.` 或空格 | 空气                                       |               |                                     |

一格 = 16×16 像素。每行长度可以不一样，解析时会按最长行用 `.` 补齐。

### 设计尺寸参考（重要）

按当前手感参数换算出来的安全距离，照着摆就不会出现"跳不过去"的断层：

- 单跳高度 ≈ **3 格**，二段跳 ≈ **5 格**
- 跑跳水平距离 ≈ **6 格**，冲刺跳 ≈ **9 格**
- 弹跳板高度 ≈ **7 格**
- ✅ 落差 ≤ 2 格、水平间距 ≤ 5 格的路线**一定过得去**
- ⚠️ 超过 6 格的间距必须靠冲刺或二段跳，别放在主线必经路上

摆放实体的技巧：把 `S` / `E` / `C` / `B` 放在**实心块的上一格**，角色刚好站在地面上（角色高 18px 比格子高，放在正中间会有一像素嵌进地面）。

### 别忘了校验

```bash
npm run check:maps
```

两个脚本各管一件事：

- `scripts/validate-maps.mjs` —— 结构检查：出生点数量、是否有终点、`S/E/C` 是否有落脚点、`B/^/~` 下方是否实心（校验逻辑在 `src/core/validate.ts`，生成器也复用同一套规则）。
- `scripts/simulate.mjs` —— **可通关性仿真**：在 Node 里用与游戏完全一致的物理规则跑一个会跳/二段跳/蹬墙跳/冲刺的 bot，报告它能否到达终点（逻辑在 `src/core/simulate.ts`）。地图画错断层时它会直接指出 bot 卡在哪一格。**注意**：bot 对平地尖刺有决策死区，尖刺图可能报 bot 死亡，属 bot 局限——结构通过即合格。

> 说明：`simulate.mjs` 把移动平台按"停在中心位置"的静态实体处理，所以移动平台只适合当可选路线，别设计成唯一通道。

## 图形化地图编辑器（editor.html）

不想手写 ASCII？项目内置一个**所见即所得的地图编辑器**：可视化画图、内嵌真实物理试玩、保存即出新关。**编辑器里跑的校验和可通关性仿真与 `check:maps` 是同一套 `src/core/` 逻辑**——面板上说"可通关"，命令行就一定能过。

### 打开

```bash
npm run dev
# 编辑器：http://localhost:5173/editor.html
# 游戏页：http://localhost:5173/（保存后刷新，新关即出现在选关界面）
```

生产构建产物为 `dist/editor.html`（此时「写入项目」不可用，保存只能用下载 / 复制）。

### 界面

左侧是 **15 个瓦片按钮**（实心 / 单向 / 横木 / 尖刺 / 岩浆 / 金币 / 出生 / 终点 / 检查点 / 弹跳 / 加速带 →← / 移动平台 M·m / 橡皮），中间是网格画布（每格 16px，瓦片色块 + 字符实时叠加），右侧是**关卡信息 / 校验 / 仿真 / 操作**面板，底部状态栏显示当前工具与光标所在格。

### 操作

| 操作 | 方式 |
| --- | --- |
| 放置 / 擦除 | 左键放置当前瓦片；右键擦除 |
| 连续画线 | 按住左键拖拽（Bresenham 自动补格，快速拖动不漏格） |
| 平移画布 | 中键拖拽 / 方向键 |
| 缩放 | 滚轮（以鼠标位置为中心，0.5x–8x） |
| 撤销 | `Ctrl+Z`（最多 60 步） |
| 试玩 / 返回 | 点「试玩」进入；试玩中 `Esc` 返回编辑、`R` 重开 |

试玩按键与游戏完全一致：`←` `→` / `A` `D` 移动、`空格` `↑` `W` 跳、`Shift` `Z` 冲刺、`↓`+跳 下穿单向平台。试玩用**真实的 `Platformer` 物理 + 与 GameScene 相同的机关判定**（尖刺 / 岩浆 / 弹跳板 / 加速带 / 移动平台 / 检查点 / 终点门），所见即所得；移动平台与仿真口径一致按"中心静止"处理，只能当可选路线。

### 载入与保存

- **载入现有**：下拉选择任意已有关卡，自动反解到画布继续编辑（改完用新文件名另存即可，不会覆盖原图）。
- **保存**：点「保存」弹窗询问，三种方式任选：

| 方式 | 说明 |
| --- | --- |
| ① 写入项目 maps/ | 仅开发模式。经 Vite 本地端点直接写进 `src/levels/maps/`；自动建议下一个编号文件名（如 `08-my-level.ts`），已有同名文件会提示「已覆盖」。保存后刷新游戏页即出现在选关界面 |
| ② 下载 .ts | 任何环境可用。下载与手写同格式的 `LevelData` 文件，放进 `src/levels/maps/` 即生效 |
| ③ 复制内容 | 任何环境可用。复制源码到剪贴板，粘贴保存为 `.ts` 文件即可 |

> 文件名规则与手写完全一致：**两位数字前缀决定选关顺序**（`04-my-level.ts`），`meta.id` 全局唯一（存档 key）。写入端点带文件名白名单校验，非法路径会被拒绝。

### 实时校验与仿真

- **校验**：每次改动即时跑结构规则（`S` 恰好 1 个、`E` ≥ 1、`S/E/C` 有落脚、`B/^/~` 坐实心），不通过会直接指出格坐标。
- **仿真**：改动后约 0.7s 自动跑 bot，也可点「跑可通关性仿真」手动触发；结论与 `npm run check:maps` 的 simulate 段完全一致。

> 沿用脚本口径：bot 对平地尖刺有决策死区，尖刺图可能报 bot 死亡——结构通过即合格。

## 自动生成地图（一条命令出图）

想快速出一张保证能通关的图？用项目自带的自动生成器 `scripts/gen-map.mjs`（已注册为 `npm run gen:map`）。它用**构造式算法**保证生成的地图**理论上一定可通关**，支持尖刺，用**难度系数控制冗余**：

```bash
node scripts/gen-map.mjs                      # 默认难度 0.5，自动编号输出到 src/levels/maps/
node scripts/gen-map.mjs -d 0.85 -l 100 -n "熔岩试炼" -t cave
node scripts/gen-map.mjs -d 0.3 --seed 42     # 同种子可复现同一张图
node scripts/gen-map.mjs -d 0.7 -c 3          # 批量生成 3 张
node scripts/gen-map.mjs --out-dir <目录>     # 输出到指定目录
node scripts/gen-map.mjs --no-simulate        # 只做结构 + 理论校验，不跑仿真
```

**CLI 选项**

| 选项 | 说明 | 默认 |
| --- | --- | --- |
| `-d, --difficulty <0.05~1.0>` | 难度系数（控制冗余量） | `0.5` |
| `-l, --length <列数>` | 地图宽度 | `80`（最小 48） |
| `-n, --name <名称>` | 关卡名 | `自动生成·难度X` |
| `-t, --theme <主题>` | `forest` / `cave` / `sky` | `forest` |
| `--seed <整数>` | 随机种子，同种子复现同一张图 | 随机 |
| `-c, --count <张数>` | 批量生成张数 | `1` |
| `-o, --out <文件名>` | 指定输出文件名 | 自动编号（如 `08-auto.ts`） |
| `--out-dir <目录>` | 输出目录 | `src/levels/maps/` |
| `--no-simulate` | 跳过仿真报告（通过标准不变） | 关 |

**难度系数 = 冗余量**（越高容错越少）：

| 系数 | 坑宽 | 尖刺 | 助跑 | 辅助机关 |
| --- | --- | --- | --- | --- |
| `0.1~0.3` | 1~3 格 | 1 格、稀疏 | 7 格 | 单向 / 移动平台多、检查点密 |
| `0.4~0.6` | 3~5 格 | 2 格 | 5 格 | 机关渐少 |
| `0.7~1.0` | 5~6 格 | 3~4 格、密集 | 3 格 | 少，靠极限跑跳 |

**如何保证可通关（三层校验，全自动）**：

1. **结构校验**：复用 `src/core/validate.ts` 规则（S 恰好 1 个、E 至少 1 个、落脚 / 坐实心）。
2. **理论可达性**：从构造上保证存在必过路线——坑宽 ≤ 6（跑跳 6 格必可越）、尖刺组宽 ≤ 4 且前后留足助跑平地、弹跳板落点安全。
3. **仿真（信息性）**：跑 `src/core/simulate.ts` 的 bot 做参考报告。生成器自动换种子重试，**优先挑 bot 零死亡的布局**；找不到则以理论可过的为准。

生成的是"可通关骨架"（地面带 + 坑 + 尖刺），建议再手动补主题机关与文案（见上面字符表与尺寸约束）。

> **注意**：simulate 的 bot 对平地尖刺有决策死区（固定步长起跳），高难度图 bot 可能死亡——这是 bot 的局限，**不代表地图不可通关**。`check:maps` 的 simulate 段同理：结构通过即合格（官方 `07-cave-hopping` 也是尖刺图，同样如此）。

## 项目结构

```
src/
├── core/                 纯逻辑层（不依赖 Phaser，可单独测试）
│   ├── config.ts         所有手感 / 尺寸常量（调手感只改这里）
│   ├── controls.ts       按键映射
│   ├── map-format.ts     地图格式、字符表、解析器、standPos()
│   ├── platformer.ts     平台跳跃状态机（AABB 碰撞 + 土狼时间 + 冲刺…）
│   ├── simulate.ts       可通关性仿真（模拟 bot 逐帧推进，check:maps 与自动生成器复用）
│   ├── validate.ts       地图结构校验（S/E/落脚/坐实心，check:maps 与自动生成器复用）
│   └── save-data.ts      localStorage 存档（最佳成绩 / 解锁进度）
├── levels/
│   ├── registry.ts       ★ 地图自动注册中心（import.meta.glob）
│   └── maps/             ★ 所有地图放这里，加文件即加关卡
├── editor/               独立地图编辑器（入口 editor.html：瓦片调色板 / 画布 / 属性面板 / 实时校验仿真 / 试玩 / 三选一保存）
├── scenes/
│   ├── BootScene.ts
│   └── GameScene.ts      把逻辑关卡渲染成 Phaser 世界
├── ui/ui.ts              DOM 覆盖层：菜单 / 选关 / 暂停 / 结算 / HUD
├── style.css
└── main.ts               入口 + UI 与场景的事件桥接
```

分层原则：**玩法规则在 `core/`（纯 TS，无 Phaser 依赖），渲染在 `scenes/`，界面在 `ui/`。**
物理是自研 AABB，没有用 Arcade Physics，方便完全掌控手感。

> 自动生成器 `scripts/gen-map.mjs` 与校验脚本 `scripts/validate-maps.mjs` / `scripts/simulate.mjs` 同为纯 Node 工具，不参与游戏运行时。

## 已实现

- 7 张自带关卡（教学 → 深坑单向平台 → 天空之塔 → 岩浆弹跳 → 移动岛屿 → 冲刺峡谷 → 洞穴尖刺）
- **自动地图生成器**（`scripts/gen-map.mjs`）：构造式生成保证理论可通关，支持尖刺、难度系数控制冗余、批量生成、种子复现
- **图形化地图编辑器**（`editor.html`）：可视化画图（15 个瓦片按钮 / 拖拽连画 / 平移缩放 / 撤销）、内嵌真实物理试玩、实时结构校验 + 可通关性仿真（与 `check:maps` 同一套 `src/core/` 逻辑）、三选一保存（写入项目 / 下载 .ts / 复制内容）
- 跑酷手感：二段跳 / 冲刺 / 蹬墙跳 / 土狼时间 / 跳跃缓冲 / 可变跳高
- 单向平台、移动平台、弹跳板、加速带、尖刺、岩浆、金币、检查点
- 选关界面 + 关卡顺序解锁 + 最佳成绩与金币记录（localStorage）
- HUD（关卡名 / 金币 / 死亡数 / 计时）、暂停菜单、通关结算、死亡闪屏与粒子
- 响应式布局（FIT 缩放 + 像素化渲染），HUD 自动贴合画布

## 已知取舍

- 终点门触发框高 30px：贴地跑进去必定触发，但高空满跳可能从门上方飞过（继续向右跑回去即可）。
- 逻辑层与渲染层是"每帧同步位置"的简单关系，角色没有逐帧动画（像素方块 + 变色表示状态），要换成精灵图的话改 `GameScene.buildPlayer` 即可。
